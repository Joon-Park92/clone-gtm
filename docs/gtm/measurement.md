# 측정 계약

주 지표: 7일 동안 이번 캠페인에 귀속되는 중복 없는 신규 사전 신청자 수.

시작/종료 시각: 미확정. Asia/Seoul(+09:00), 시작 포함·종료 제외, 정확히 7일. 첫 실제 실행 전에 설정에 고정하고 이후 변경 시 별도 실험으로 기록한다. 행사 기간과 일치 여부는 별도 확인한다.

실제 접수 확인된 신청만 인정한다. 기존 신청자, 중복, 내부 테스트, 스팸을 제외한다. 출처 불명은 별도 집계. 캠페인 전체에서 같은 사람을 한 번만 계산한다. 이메일 기준은 앞뒤 공백 제거와 비교 규칙을 담당자가 확정한다. Gmail 점/플러스 제거 같은 제공자별 규칙을 일괄 적용하지 않는다. 복수 이메일의 동일인 여부를 알 수 없으면 그 한계를 명시한다.

우선 양식까지 campaign_id/asset_id 보존. 이메일이면 제목 코드 또는 유입 경로 자기보고로 수동 귀속하며 한계를 기록한다. 콘텐츠별 식별이 없으면 캠페인 수준만 집계한다. 코어는 UTM만으로 완료를 인정하지 않는다.

MeasurementAdapter는 실제 수신 증거와 기존 신청자 기준을 확인하고 원본/중복 판별키를 비공개로 관리한다. 코어에 개인정보를 반환하지 않고 기간·관측 시각·캠페인 누적 집계·제외 집계·정제된 증거 참조·방법/한계를 반환한다. 자기보고 귀속은 source_method에 명시한다.

null = 미측정. 0 = 측정 완료 후 해당 신청 없음. 누적 스냅샷끼리 합산하지 않는다. 클릭, 방문, 신청 버튼 클릭은 보조 지표이며 접수가 아니다. 원본 메일·이메일 주소·원본 스크린샷·개인정보는 private/에서만 관리한다. 정제된 증거 파일만 Git에 명시적으로 추가한다.

실연결 검증: 내부 테스트 신청 1건으로 접수·캠페인 코드 보존 확인 → 테스트 제외 확인 → 기존 신청자 기준 시점 고정 → 기간 고정 → 시작. 테스트 신청 전 발송 승인이 필요하다.

## 실제 CTA 확인 결과 (2026-10-24)

[공개 HTTP 검증](../ref/evidence/mu-cta-20261024.json)으로 /ko → /w/go/ko → support@pairful.ai 메일 작성 경로 확인. /w/go/ko에 campaign_id·utm_campaign을 붙인 검사에서는 메일 제목/본문으로 코드가 전달되지 않았다. 서버 분석이 해당 파라미터를 저장하는지는 검사하지 않았다. 제목 코드가 사전 입력된 별도 mailto 또는 사용자의 제목 입력이 필요하다. 현재 귀속 준비안은 아래와 같다. 메일이 실제 수신되기 전에는 신청 완료로 집계하지 않는다.

## 현재 귀속 준비안과 병렬 실험 조건

기본 제목은 ‘무 먼저 써보고 싶어요’다. `[MU-KO-001]`은 이번 캠페인을 구분하려는 제목 코드 제안이며 할인·혜택이 아니다. 사용자 채택·실수신 검증 전이고 현재 게시 초안에는 적용하지 않았다. mailto 링크의 실제 Threads 동작도 미확인이다.

캠페인 코드만 있으면 전체 성과만 집계한다. 높은·낮은 가설 비교에는 deployment_id 또는 동등한 배포별 식별이 실제 신청까지 이어져야 한다. 동일인의 최초로 검증된 배포 코드를 기준으로 한 번 귀속하고 모호하면 캠페인 전체에만 포함한다. 이 방식은 유입 연관의 근거이며 인과 효과의 증거가 아니다.

## 실제 수신 Adapter의 처리

1. 시작 직전 기존 신청자를 고정하고 비공개 기준 버전을 남긴다.
2. 고정 기간의 실제 수신 시각으로 후보를 조회한다. 전달본·자동응답·문의·반송은 신청으로 세지 않는다.
3. 테스트·스팸·기존·중복을 정해진 우선순위로 제외한다. 원본 식별키와 메일은 private 영역에 둔다.
4. 현재 신청의 실제 제목·검증된 양식 필드에서 귀속을 읽는다. 답장 인용·검색 스니펫만으로 귀속하지 않는다.
5. 사람 단위 중복을 제거하고, 알려지지 않은 복수 이메일 등 한계를 기록한다. 동일인의 나중 귀속 근거는 감사 기록 후 반영할 수 있으나 중복 집계하지 않는다.
6. 접수·기준·귀속·완전성 확인 후 정제된 집계와 증거를 출력한다. 정정으로 누적 신청이 감소하면 감사 대상으로 남긴다.

연결 전 입력은 `unconnected` 또는 `pending`이다. `measured`는 정확한 기간·관측 시각·수집 마감, 기존 기준·접수 검증, campaign 범위 중복 제거, 설정과 같은 source_method, 제외 집계, EV- 증거 ID를 요구한다. 자세한 검사는 src/loop.py에 있다.

포트폴리오 비교는 게시 후 고정 24시간이 완료된 배포만 대상으로 한다. complete·verified_receipts·baseline_excluded·campaign_deduplicated와 익명 credit_ids를 검사한다. 같은 credit_id의 복수 배포 사용은 거부한다. 7일 종료에 관측 구간이 잘리면 완전한 구간과 비교하지 않고 최종 캠페인 집계와 분리한다. 이 계약은 src/portfolio.py와 [병렬 설계](portfolio-loop.md)에 있다.
