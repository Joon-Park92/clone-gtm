# Threads에서 첫 고객을 찾는 배포 설계

2026-10-24 사용자 결정: 첫 채널은 Threads. 기존 독자 없이 시작하며 Threads 계정은 사용자가 생성 완료했다고 확인했다. Disquiet 주경로와 심사 24시간 대기 제안은 현재 계획에서 제외한다. 이전 조사와 결정은 Git·활동 기록에 남긴다.

## 시작 순서

1. 사용자 소유 Threads 계정은 생성 완료다. 사용자가 공개 @아이디 mu.agent를 제공했다. 공개 프로필 조회와 로그인·게시 연결 상태를 별도로 검증한다.
2. Mu 제작자 관계와 사전 사용 모집 상태를 드러내는 프로필을 준비한다.
3. [첫 게시 검토본](publish-packet.md)을 계정·첨부물·링크와 함께 사용자에게 보여준다.
4. 신청 귀속 방식·실제 접수·7일 측정 구간을 확인한 뒤 승인된 최종본을 게시한다.
5. 실제 게시 URL·시각을 기록하고, 반복 루프에서 반응과 신청을 관측한다.

## 독자 0에서의 도달 가설

예약 확인 상황을 묘사한 공개 글과 관련 주제 하나로 관심 있는 독자에게 발견될 가능성을 시험한다. 관련 예약 대화는 읽기 조사하고 고객이 표현하는 불편을 다음 글에 반영한다. 새 계정이나 글 하나의 자연 노출을 보장하지 않는다. 댓글·멘션·DM을 자동 배포 수단으로 사용하지 않는다. 직접 답글을 올릴 때도 사용자 검토 범위를 확인한다.

[Meta 기능 안내](https://about.fb.com/news/2025/03/new-threads-features-more-personalized-experience-you-control/)는 프로필·게시물 링크, 주제 및 링크 방문 지표 기능을 설명한다. 기능 안내는 우리 계정의 노출·전환 실적이 아니며 실제 계정에서 제공되는 지표만 기록한다. mailto 링크 지원 여부는 미확인이다.

## 첫 관측과 다음 행동

- 노출 미측정: 가용 지표부터 확인하고 제품 수요를 판단하지 않는다.
- 노출 부족: 주제·도달 경로 하나를 점검한다. 같은 글을 반복 게시하지 않는다.
- 노출 후 방문 부족: 첫 문장 하나를 수정한 새 검토본을 준비한다.
- 방문 후 신청 부족: 신청 경로·귀속 누락을 먼저 확인한다.
- 예약 성공·선점 요구만 있는 응답: 조회 위임 수요와 구분한다.
- 실제 귀속 신청: 같은 문제의 후속 예시를 준비한다.

모집 글 자체로 고객 경험을 새로 확인할 수 있으므로 공개 원문에서 적격 고객을 미리 찾는 것을 모든 게시의 필수 조건으로 삼지 않는다. 댓글·좋아요를 신청으로 세지 않는다. 캠페인 신규 신청자는 중복 없이 세고 식당 ICP 적합성은 별도로 기록한다.

## 반복과 승인

최초 1회 수동 시작 뒤 하루 한 번 자동 루프를 요청한 상태다. SchedulerAdapter와 실행 런타임은 아직 연결하지 않았다. 자동화 범위는 조사·관측·분석·초안·기록·발표 문서 갱신이며 실제 게시 전에는 매번 최종본 사용자 검토가 필요하다. 승인 대기 중에도 관측·기록을 계속한다. 다른 채널로 변경할 때는 별도 결정과 게시 승인을 남긴다.
