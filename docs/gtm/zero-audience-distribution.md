# 계정·독자 0에서 시작하는 배포 설계

작성: 2026-10-24 / campaign_id MU-KO-001.
전제: 사용자가 게시 가능한 기존 계정·커뮤니티가 없다고 확인했다. 계정 생성·외부 게시·DM·메일 발송은 실행하지 않았다. 사용자 추가 지시: 실제 게시 전 반드시 검토받는다. 이 문서는 **첫 모집 채널에 대한 가설**이며 검증된 고객 획득 채널이 아니다.

## 권고

**디스콰이엇에 Mu 제품을 등록하고, 승인된 제품에 연결한 공개 모집 포스트 하나로 시작하는 경로를 권고한다.** 제품을 만드는 사람이 제품을 소개하는 맥락이 명확하고, 현재 가입·등록 절차를 공개 1차자료에서 확인할 수 있기 때문이다. 인기 식당 예약 경험자가 충분히 있다는 근거는 없으므로 응답에서 고객 적합성을 확인한다. 제품 검토 통과나 노출·신청 수, 처리 시간을 보장하지 않는다. 주경로는 디스콰이엇 하나로 정하고, 아래 24시간 대기 한도를 넘으면 Threads 전환을 검토한다. 이는 사용자 승인 전 운영 제안이다.

중요한 변경: ‘디스콰이엇 메이커로그 신규 작성’은 현재 경로로 쓰지 않는다. [현 운영자 공지](https://disquiet.io/announcement)에 따르면 기존 메이커로그에 해당하는 아티클 신규 작성은 잠시 중단되었고, 메인 피드에는 제품에 연결된 포스트만 노출된다. 제품은 본인이 만든 것만 등록하며 작성→검토 요청→승인을 거친다. 이 공지는 날짜가 본문에 표시되지 않아 2026-10-24 조회 기준으로 기록한다. 2024년의 기존 [프로덕트 업로드 팁](https://disquiet.io/articles/BrsV5v)은 현재 작성 절차를 대체하지 못한다. 현 공지는 DM·알림·전역검색(프로필 검색만 유지)·트렌딩·뉴스레터 등 제거도 설명한다. 해당 기능을 통한 초기 확산을 계획에 넣지 않는다.

## 적격 고객 원문 0건을 다루는 방법

현재 조사에서 조회 조작 불편과 위임 의사를 모두 만족하는 고객을 확인하지 못했다. 이 결과는 명시적 문제 근거가 약하다는 뜻이지 **모집 글을 영구적으로 게시할 수 없다는 조건**이 되어서는 안 된다.

기존 루프의 조건은 다음처럼 조정하는 것이 적절하다.

- 기존 공개 대화에 직접 참여할 때: 그 대화의 문제 적합성과 참여 규칙을 먼저 확인한다.
- 제품 소개 공간에 자체 모집 포스트를 올릴 때: 제품 관계·준비 단계·검증할 사용 상황을 밝히고 문제 경험자를 모집한다. 사전 적격 고객 원문 1건은 필수 선행 조건으로 두지 않는다.
- 사후 판정: 응답자 중 실제 인기 식당 예약 경험, 앱 확인 과정의 수고, 맡겨보고 싶은 의사를 구분해 기록한다. 제품 관심만 있는 사람도 실제 사전 신청이면 캠페인 주 지표에는 포함하되, 식당 ICP 적합성은 별도 미확인으로 남긴다.
- 댓글·호기심·좋아요는 사전 신청 완료가 아니다. 접수된 신규 신청만 주 지표에 포함한다.

현재 근거 없는 위임 수요를 기존 사실처럼 문안에 쓰지 않는다. 모집 포스트 자체가 그 가설을 검증하는 첫 관측 수단이다.

## 첫 배포 흐름

1. **에이전트가 준비:** Mu 소개·실제 단계·한국어 제품 링크·대표 사용 예시·모집 본문을 하나의 검토 패키지로 만든다. 필수 이미지나 추가 필드는 로그인 후 확인되면 그때 준비한다. 사용자는 문구를 다시 작성하지 않는다.
2. **사용자 최소 작업:** 자신이 관리할 이메일/Google 계정으로 가입·인증 및 필요한 약관 절차를 직접 완료한다. 에이전트에 인증 코드나 비밀번호를 넘길 필요가 없다. 생성된 계정의 공개 식별자만 작업 기록에 연결한다.
3. **제품 등록:** 자신이 만든 Mu임을 밝히고 ‘사전 사용 신청 단계’로 등록 내용을 준비한다. 실제 등록·검토 요청은 해당 내용과 계정을 사용자에게 보여준 뒤 승인 범위에서 실행한다. 출시 완료나 현재 즉시 사용 가능으로 표시하지 않는다.
4. **게시 준비:** 제품 검토가 통과하고 포스트 작성이 가능해지면 해당 제품에 연결한 모집 글 하나를 검토한다. 본문은 예약 확인 사례 → 범용 앱 자동화 비서 → 사전 신청 순서를 유지한다.
5. **응답 구분:** 질문은 하나만 둔다. ‘인기 식당을 예약할 때, 앱에서 확인하는 과정 중 가장 번거로웠던 일은 무엇인가요?’ 답변은 선택 사항이며 바로 신청할 수 있다. 좌석 경쟁만의 문제인지 앱 조작 수고인지 구분한다.
6. **실제 접수:** 게시물의 한국어 Mu 링크는 제품 설명용으로 두고, 실제 신청 CTA는 제목 코드 [MU-KO-001]이 사전 입력된 mailto를 사용한다. 채널이 mailto를 지원하지 않으면 공개 신청 주소와 제목 코드의 복사 안내로 바꾼 최종본을 다시 검토한다. 기존 랜딩 CTA에는 코드가 자동 전달되지 않으므로 해당 링크만으로 캠페인 귀속을 보장하지 않는다. 본문에 개인정보를 댓글로 남기도록 요구하지 않는다. 문의자가 요청하지 않은 DM·메일을 보내지 않는다.
7. **24시간 후 관측:** 게시 영수증·확인 가능한 노출·응답·실제 신규 신청을 기록한다. 공개하지 않는 노출 지표는 null로 남긴다. 반응이 없으면 제품 수요 부재와 배포 부족을 혼동하지 않는다.

최초 게시로 유입이 없으면 다른 글에 홍보 댓글을 반복하거나 업보트를 교환하지 않는다. 같은 게시물에서 받은 질문에 필요한 답을 준비하고, 새로운 관측/변경점이 생겼을 때 후속 공개 포스트 여부를 판단한다. 후속 외부 답글도 사전에 정한 승인 범위에서 실행한다.

## 모집 포스트에 포함할 요소

- 관계 공개: ‘Mu를 만드는 팀입니다.’
- 사용 상황: ‘이번 토요일 저녁 두 명, 예약 가능한지 앱에서 확인하는 일.’
- 제품 범위: 카카오톡으로 모바일 앱 작업을 부탁하는 비서; 배송 조회·장바구니도 소개.
- 준비 상태: 현재 사전 사용 신청 단계. 예약 성공·좌석 선점·즉시 이용 보장 없음.
- 단일 전환: 제목 코드가 입력된 Mu 사전 신청 메일 링크. 제품 소개 링크는 설명용이다.
- 선택 질문: 앱 확인 과정에서 번거로웠던 일 하나.

이는 문구 구성 지침이다. 정확한 게시 본문과 asset_id는 게시 패키지에서 관리하고, 여기에서 별도 본문 버전을 만들지 않는다.

## 게시 전 필수 검토

실제 게시 전 **제목·본문·첨부물·링크·채널·계정의 최종본 전체**를 사용자에게 보여주고 명시적인 승인을 받아야 한다. 전략 방향이나 초안에 대한 동의는 게시 승인이 아니다. 하나라도 변경되면 다시 검토받는다. 현재 승인된 범위는 설계·조사·준비이며, 문서의 경로 선택이나 24시간 전환 조건은 자동 게시 권한을 부여하지 않는다.

## 실행 대기 조건과 독립 작업

실계정, 제품 등록 적격성/승인, 실제 게시 승인, 신청 접수·귀속 검증과 측정 기간이 준비되면 측정 가능한 첫 게시를 진행한다. 그전에도 프로필·제품 등록 원고·포스트·응답 분류·측정 계약은 완성할 수 있다.

제품 검토가 지연되면 대기 시간을 기록한다. 지연을 피하려고 미출시 사실을 숨기거나 다른 게시 유형으로 우회하지 않는다.

대안의 구체 조건(운영 제안): 제품 검토 요청 시각부터 24시간 후에도 미승인이면, 남은 7일 운영 시간을 고려해 Threads로 첫 배포 채널을 바꾸는 결정을 사용자에게 제시한다. 미출시 제품이 등록 불가로 확인되면 24시간을 기다리지 않고 동일 전환을 제시한다. 게시되지 않은 디스콰이엇과 동시 성과 비교를 하지 않는다.

Threads 전환 패키지는 미리 준비한다: 같은 Mu 소개와 요청 예시를 500자 이하 한국어 공개 포스트 하나로 압축하고, 프로필에는 제품 관계와 사전 신청 단계 및 한국어 Mu 링크를 넣는다. 사용자가 관리할 Instagram/Threads 계정 생성·인증 조건을 현재 화면에서 확인하고, 실제 계정과 본문에 대한 승인을 받은 뒤 공개한다. 도움말 접근 실패 때문에 가입이 반드시 바로 완료된다고 약속하지 않는다. 새로운 계정의 게시물은 추천될 수도 있지만 도달을 보장하지 않는다. 관련 주제를 붙일 수 있으면 예약 상황에 맞는 주제 하나만 사용하고 홍보 답글·멘션·DM을 배포 수단으로 삼지 않는다. [Meta의 링크·주제 안내](https://about.fb.com/news/2025/03/new-threads-features-more-personalized-experience-you-control/)는 기능 가능성의 근거이지 노출 실적의 근거가 아니다.

실제로 첫 게시가 된 채널을 기준으로 24시간 후 게시 영수증·가용 노출 지표·신청을 확인한다. 노출이 부족하면 제품 가설을 버리지 않고 배포 병목으로 기록한다. 다른 채널로 바꾸는 경우 **채널 하나 변경**을 명시하고 해당 시점·asset_id를 구분한다. 첫 60분의 완료 기준은 검토 가능한 패키지·계정 단계·측정 계약의 준비이며, 플랫폼의 승인/도달까지 완료했다고 주장하지 않는다.

## 관측할 숫자

주 지표는 캠페인 귀속 중복 없는 신규 사전 신청자 수 그대로 유지한다. 보조적으로 예약 경험 응답 수, 앱 조회 수고를 직접 표현한 응답 수, 사용 희망 응답 수를 분리한다. 익명 댓글의 동일인 여부가 불명확하면 ‘응답 건수’로 기록한다. 등록 승인·게시 성공·조회·댓글·계정 팔로워 수는 신청이 아니다.

계정·제품 등록·게시·메일 발송·실적 측정은 이 문서를 만드는 동안 실행하지 않았다.
