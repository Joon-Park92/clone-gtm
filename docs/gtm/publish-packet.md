# 첫 게시 패킷

작성 기준: 2026-10-24. campaign_id: MU-KO-001 / experiment_id: EXP-MU-KO-001.
상태: 검토 가능한 초안 완성, 채널·계정 미확정, 외부 게시 미승인·미실행.

## 잠정 채널과 목적

잠정 후보는 Disquiet 메이커로그다. [프로덕트 업로드 팁](https://disquiet.io/articles/BrsV5v)은 제품 소개와 피드백 요청의 맥락을 제공한다. 이 문서는 2024-05-13 게시된 가이드이며 현재의 계정 생성·게시·링크 지원 가능 여부까지 확인한 것은 아니다. 식당 예약 ICP가 해당 채널에 있다는 근거는 아직 없으므로, 채널 확정이나 고객 검증 완료로 기록하지 않는다.

고객 원문에 광고 댓글을 남기는 방식은 사용하지 않는다. 오마카세 갤러리는 [공지](https://gall.dcinside.com/mgallery/board/view/?id=omakase&no=189249&page=1)에 광고 제재가 명시되어 직접 홍보 후보에서 제외한다.

핵심: 인기 식당 예약 확인으로 관심 → 범용 모바일 앱 자동화 비서 Mu → 사전 사용 신청. 팀이 소개하는 제품임을 공개하고, 실제 사용 후기나 검증된 데모처럼 표현하지 않는다.

## 게시 제목

인기 식당 예약 확인부터, 카카오톡으로 앱 작업을 맡기는 Mu

## CTA와 귀속 — 내부 기록

제품 설명은 한국어 랜딩으로 연결하고, 신청 CTA는 수신처가 확인된 메일 작성 링크에 캠페인 코드가 포함된 제목을 넣는다. 별도 폼이나 랜딩 변경은 필요하지 않다.

- 수신처: support@pairful.ai (공개 신청 경로 확인).
- 사전 입력 제목: `[MU-KO-001] 무 먼저 써보고 싶어요`.
- 공개 CTA의 mailto는 subject만 채운다. 본문은 강제하지 않는다.
- 메일 작성 화면 열기·버튼 클릭은 신청 완료가 아니다. 실제 수신 확인 후 제외·중복 제거·귀속을 적용한다.
- 기존 `/w/go/ko`에 캠페인 쿼리를 추가하는 것만으로는 메일 제목·본문에 코드가 보존되지 않았다. 확인 증거: [CTA HTTP 점검](../ref/evidence/mu-cta-20261024.json).
- 해당 채널이 mailto 링크를 허용하고 정상 표시하는지는 게시 전 미리보기에서 확인해야 한다. 링크를 허용하지 않으면 제목 코드 수동 입력 안내로 바꾸고 **본문 해시·asset_id를 다시 계산한 새 검토본**을 만든다. 현재 승인본을 임의 변경한 채 게시하지 않는다.
- 코드 누락 신청은 이 콘텐츠의 전환으로 자동 분류하지 않는다. 추가 출처 확인 없으면 출처 불명으로 둔다.
- 콘텐츠별 태그는 넣지 않았으므로 현재 귀속은 캠페인 단위다. 여러 콘텐츠의 개별 성과 비교에 사용하지 않는다.

메일 링크를 지원하지 않는 채널에서 사용할 복사 대안(현재 공개 본문에는 미적용):

> 사전 사용을 신청하려면 support@pairful.ai로 메일을 보내주세요. 제목은 `[MU-KO-001] 무 먼저 써보고 싶어요`로 적어주시면 됩니다.

이 대안을 넣으면 공개 본문이 달라지므로 위 링크형 초안과 별도 검토하고 hash/asset_id를 다시 계산한다.

관련 설계: [신청 귀속 준비](attribution-setup.md), [측정 계약](measurement.md).

## 콘텐츠 식별과 정확한 승인 범위

이 패킷은 **제목 + LF 두 개 + 공개 본문**의 UTF-8 바이트를 해시한다. 마지막 개행은 포함하지 않는다. PUBLIC_BODY 주석 및 내부 기록은 공개 본문에 포함하지 않는다.

- asset_id: `MU-KO-001-A-7e8efe601a3cbc5b`
- content_sha256: `7e8efe601a3cbc5b68f07aae854923b76257579a12e1b987c7724bb201f20a53`
- channel: `pending` (잠정 후보: Disquiet 메이커로그)
- account_ref: `pending`
- approval_status: `pending`
- publication_status: `not_posted`
- published_url: `null`
- published_at: `null`

현재 `src/loop.py`는 `config.draft.body`만 해시한다. 이 패킷을 실행기에 옮길 때는 제목과 본문을 위 직렬화 방식으로 합쳐 `draft.body`에 넣어야 같은 hash/asset_id가 된다. 제목 필드를 별도 저장할 경우 코어의 승인 계약을 먼저 조정해야 한다. 현재 config의 짧은 합의 문안과 이 채널별 패킷은 서로 다른 콘텐츠이므로 승인이나 asset_id를 재사용하지 않는다.

## 게시 전 사람이 확인할 사항 — 공개 본문에 넣지 않음

| 항목 | 현재 상태 | 필요한 확인 |
| --- | --- | --- |
| 채널 적합성 | 잠정 | 식당 예약 확인 수요를 가진 독자와 연결되는지, 현재 게시 규칙 |
| 게시 계정 | 미정 | 사용 가능한 계정과 게시 주체 |
| 실제 지원 범위 | 미검증 | 예약 가능 여부 조회·배송 조회·장바구니·승인 흐름의 소개 표현이 정확한지 |
| 즉시 이용 오해 | 문구 반영 | 사전 신청 단계가 본문에서 명확한지 |
| 예약 성공·선점 오해 | 조회 예시로 제한 | 예약 가능한 시간 확인이라는 약속을 승인하는지 |
| 메일 링크 | URL 형식 검증, 채널 동작 미검증 | 해당 채널 미리보기 및 메일 작성 화면의 제목 코드 |
| 수신·귀속 | 미연결 | 담당 수신함 확인, 테스트 제외, 기존 신청자 기준·측정 기간 고정 |
| 외부 게시 승인 | 없음 | 위 제목·본문·계정·채널을 묶은 1회 게시 승인 |

내부 검토는 콘텐츠와 실행 준비 점검이며 실제 전환 증거가 아니다. 외부 게시·DM·메일 발송·테스트 신청은 수행하지 않았다.

## 메인 통합 상태

제목 + LF 두 개 + 공개 본문을 config/loop.json의 draft.body로 옮겨 해시 일치를 확인했다. 로컬 실행의 asset_id도 위 값과 일치한다. 검토용 설정 반영이며 실제 게시 승인이나 채널 확정을 뜻하지 않는다.
