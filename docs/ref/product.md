# Mu 제품 근거

출처: 사용자가 2026-10-24 제공한 영문 랜딩 페이지 본문. 페이지: https://mu.pairful.ai/en (사용자가 제공한 내용이며 이 세션에서 웹 본문 조회로 검증하지 못함).

## 제품 소개상 주장

Pairful의 Mu는 채팅으로 요청하면 직접 앱을 열고 조작하여 결과를 알려주는 개인 비서다. 제공된 영문 본문은 KakaoTalk을 명시한다. 이전 인계에는 iMessage도 있었지만 이번 본문에는 없으므로 첫 콘텐츠는 KakaoTalk만 사용한다.

흐름: 채팅 요청 → Mu가 앱을 열고 탐색·조작 → 결과 메시지. ‘매일 아침 8시’ 같은 예약 요청도 소개한다. 별도 설치·설정 없이 사용한다고 설명한다. 쇼핑·예약·교통·지도 등 80여 일상 앱으로 시작한다고 소개한다.

예시: 쿠팡 배송 확인, 캐치테이블 토요일 저녁 2인 가능 여부, 금요일 부산행 KTX 잔여석, 올리브영 장바구니, 메가박스 상영작, 출근 지하철 시간, 아침 메일 요약, 카카오 T 귀가, 컬리 재주문 장바구니, 스타벅스 커피 주문, KREAM 가격, 아침 날씨 알림.

## 승인·개인정보에 관한 소개

결제·예약 확정·저장된 로그인 사용마다 사용자 승인을 요청한다고 설명한다. 비밀번호·카드는 기기에만 있는 키로 잠긴 보관함에 저장하며 운영자도 열 수 없다고 주장한다. 광고 없음, 요청 처리만을 위한 데이터 사용, 판매하지 않음, 계정 삭제 시 기록·저장 정보 삭제를 소개한다. 이 내용은 제품의 설명이며 기술·보안 검증 결과가 아니다. 첫 홍보 콘텐츠에서 검증되지 않은 보안 보장을 확대하지 않는다.

## 신청과 확인 상태

CTA는 ‘Meet Mu early’, ‘Ask for early access’. 연락하면 순차 회신하는 사전 사용 모집이다. footer에 공개 지원 주소 support@pairful.ai가 있지만 **실제 신청 버튼 목적지라고 확인된 것은 아니다**. 개인 연락처가 아닌 공개 제품 지원 정보로만 기록한다. 실제 CTA 링크, 수신함, 기능 동작, 승인 흐름, 보안 구현, 현재 사용 가능 지역은 미확인이다. FAQ 질문은 있으나 답변 본문은 제공되지 않았다.

## 첫 실험에서 쓸 범위

카카오톡으로 식당 예약 가능 여부 조회 같은 앱 작업을 부탁하는 사용 방식을 소개하고 사전 신청 안내로 연결한다. 즉시 이용·예약 성공·좌석 확보를 보장하지 않는다. 제품 소개의 예시를 실제 사용자 후기나 실증 데모로 표현하지 않는다.

## 첫 GTM 방향 추가 (2026-10-24)

사용자가 인기 식당 예약을 첫 사례로 지정하고 모바일 앱에서 수행하는 작업의 번거로움과 모바일 앱 자동화 가치를 강조하도록 지시했다. 이를 포지셔닝에 반영한다. 모든 식당 예약이 모바일에서만 가능하다는 사실이나 특정 서비스의 앱 전용 여부를 검증한 것은 아니다. 상세 정의는 [GTM 전략](../gtm/strategy.md)을 따른다.

사용자 추가 설명: Mu의 제품 범위는 모든 앱 자동화를 지향하는 범용 앱 자동화다. 사용자는 인기 식당 사례로 유입시키되 범용 개인 비서라는 정체성을 함께 보여주는 메시지에 동의했다. 기존 제공 랜딩의 ‘80여 앱’ 설명과 구분해 기록하며, 모든 개별 앱에서의 동작을 이 세션에서 검증한 것은 아니다.
