# 실제 반응으로 Mu GTM 루프 실행

PLAN.md, config/loop.json, docs/gtm/rubric.md, docs/gtm/reaction-collection.md와 이전 실행을 읽는다. 주 지표는 7일 귀속 신규 신청자 수다.

1. 같은 캠페인의 모든 게시 URL을 확인한다. 이전 게시글의 댓글·답글과 등록된 커뮤니티 대화를 수집한다. 긍정만 고르지 않는다. 범위·시각·누락·중복을 기록한다. 없거나 접근 못하면 미수집으로 남긴다.
2. 정제된 반응을 FeedbackAdapter에 제공한다. 원문 관측과 분류 이유를 분리하고 작성자·ICP가 불명확하면 인정된 여러 고객으로 세지 않는다.
3. 실제 신청 스냅샷을 수집한다. 접수·귀속·기존 신청자·중복 제외를 확인하고 미측정과 0을 구분한다.
4. 이전 실험의 예상과 이번 반응·신청 증분을 비교한다. 도달·기간·수집 범위·귀속 수준이 다르면 효과 판단을 보류한다. 커뮤니티 의견을 캠페인 성과로 취급하지 않는다.
5. 반응 Rubric으로 신청 마찰·오해·신뢰·문제 적합성 중 근거가 있는 병목을 선택한다. 새 근거가 없으면 유지한다. 의견 하나면 맥락·재현 확인을 먼저 한다.
6. 근거 ID·대안 설명·변경 하나·고정 조건·예상 반응과 신청·관측 기간·중단 조건을 기록한다. 콘텐츠 변경은 이 실험을 실행하는 수단이다. 문안 점수만으로 재작성하지 않는다.
7. prompts/review-and-refine.md로 주장·사전 사용 상태·최종 게시 범위를 검토한다. 사용자 명시 승인 전 게시·답글·DM·메일을 보내지 않는다.
8. 실행 artifact·활동 이력·PRESENTATION.md와 상세 발표 문서를 갱신한다. 다음 24시간 관측을 준비하되 실제 등록 없이 예약됐다고 쓰지 않는다.

코어의 next_action은 반응 기반 후보이며 metric_diagnostic은 집계 기반 보조 진단이다. 자동 분류·API 조회·모델 호출이 연결되지 않았다면 Mock/수동 입력 상태를 명시한다. 과거 누적 신청을 새 성공으로 주장하거나 합성 결과를 실제 성과로 쓰지 않는다.
