# 일별 Mu GTM 실행 지시

PLAN.md, docs/plan/first-loop.md, 설정, 제품 사실, 측정 계약, 가장 최근 실행을 읽는다. 에이전트 하나가 진행한다.

1. 이전 관측과 다음 변경을 읽고 이번 주요 변경 하나 또는 추가 관측을 정한다. 추천은 자동 적용되지 않으므로 적용/보류 이유를 change_note에 남긴다.
2. ResearchAdapter에서 원문과 시각·불편·적합성을 받는다. 없으면 research_pending으로 기록하고 가설 초안은 계속 작성한다.
3. DraftAdapter에서 인기 식당 예약 확인 예시 → 범용 모바일 앱 자동화 비서 → Mu 사전 신청의 흐름으로 한국어 콘텐츠 하나, asset_id, CTA, 귀속 방법을 만든다. 즉시 이용/예약 보장 표현 금지.
4. 사람의 정확한 본문·계정·채널 승인을 확인한다. 승인 전에는 게시하지 않는다.
5. PublishAdapter 영수증을 확인한다. posted는 실제 URL·시각이 있어야 한다. uncertain이면 재게시하지 않고 확인한다.
6. 게시와 독립적으로 MeasurementAdapter의 캠페인 누적 스냅샷을 확인한다. null을 0으로 바꾸거나 누적값을 합하지 않는다.
7. 관측·해석·미측정·증거·다음 주요 변경 하나를 기록한다. 작은 표본의 인과 효과를 주장하지 않는다.
8. 새 실행 파일을 저장한다. 동시 실행과 과거 실행 덮어쓰기를 금지한다. 개인정보 제외 확인 후 Git에 기록한다.
9. 최초 수동 시작 후 SchedulerAdapter로 매일 에이전트 런타임을 호출하는 운영 방식이다. 미연결이면 automatic_pending_connection으로 기록하고 예약 완료라고 말하지 않는다. 게시 승인 대기 중에도 관측·분석·기록을 계속한다.
10. 매 실행·주요 결정 후 docs/gtm/presentation.md를 기준 시각·실제 관측·학습·다음 행동으로 갱신한다. 세션 밖 갱신은 런타임 연결 전에는 실행되지 않는다.

외부 게시/DM/메일 발송/유료 집행 승인은 현재 없다. MCP 연결은 가정이고 구체 구현은 연기됐다. 사용자가 승인한 범위에서만 실제 외부 실행한다.

사용자 명시 지시(2026-10-24): 외부 게시 전 제목·본문·첨부물·링크·채널·계정 최종본을 보여주고 승인을 받는다. 내용 또는 대상 변경 시 재검토한다. 계획·실행의 차이, 실제 결과, 다음 행동을 docs/plan/activity-log.md 및 새 runs 기록에 남긴다. 기존 실행 결과를 덮어쓰지 않는다. 현 코어의 본문 해시만으로 첨부물까지 검토됐다고 가정하지 않는다.

콘텐츠를 바꾸기 전 prompts/review-and-refine.md를 실행한다. 판단 기준은 docs/gtm/rubric.md다. 새 근거 없음은 유지의 근거이며, 같은 누적 성과로 매일 새 문안을 만들지 않는다. 전후 평가·가설·예상 관측·중단 조건을 보존한다.
